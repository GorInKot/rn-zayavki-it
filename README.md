# Система заявок на автоматизацию

Вкладка корпоративного портала, через которую сотрудники подают заявки на автоматизацию процессов, а группа автоматизации их рассматривает и ведёт до внедрения.

Система заменяет прототип `Sistema_zayavok_na_avtomatizatsiyu.html`: в нём были 83 дефекта, включая четыре полностью неработающие функции. Как они закрыты — в конце файла.

| Часть | Технологии |
|---|---|
| `backend/` | Python 3.13, FastAPI, SQLAlchemy 2, Alembic |
| `frontend/` | React 19, TypeScript, React Router 7, TanStack Query, Vite |
| База данных | PostgreSQL 16 |
| Публикация | Docker Compose: `db`, `backend`, `frontend` (nginx раздаёт интерфейс и проксирует API) |

Жизненный цикл заявки и переходы между статусами описаны в [docs/request_lifecycle.md](docs/request_lifecycle.md).

---

## Быстрый старт с демо-данными

Нужен только Docker.

```bash
docker compose up -d --build
docker compose exec backend python -m app.seed
```

Откройте http://127.0.0.1:8080. Без файла `.env` система работает в режиме разработки: пользователь выбирается в правом верхнем углу. Администратор — «Орлов Сергей Николаевич», остальные — заявители.

Чтобы пересоздать демо-набор: `docker compose exec backend python -m app.seed --reset` (удаляет все заявки).

## Установка на сервер

1. Скопируйте `.env.example` в `.env` и заполните: пароль базы, `APP_BASE_PATH`, `PORTAL_ORIGINS`, режим авторизации и группы администраторов. Каждая настройка описана в самом файле.
2. Запустите `docker compose up -d --build`. Миграции применяются автоматически при старте backend.
3. Сверьте производственный календарь (см. ниже).
4. Настройте на прокси портала маршрут `APP_BASE_PATH` → `http://<сервер>:${HTTP_PORT}`.

При `ENVIRONMENT=production` документация API отключена, а режим `AUTH_MODE=dev` запрещён: сервис не запустится с ним.

## Подключение к порталу

Своего входа у системы нет — пользователь уже вошёл в портал через Active Directory. Портал должен сообщать системе, кто пользователь. Поддерживаются два способа, выбор — через `AUTH_MODE`.

### Вопросы к команде портала

1. Как портал передаёт личность: заголовками от обратного прокси или токеном JWT?
2. Для заголовков — их имена, IP-адреса прокси и кодировка кириллицы (UTF-8 или percent-encoding — поддерживаются оба варианта).
3. Для JWT — адрес JWKS или открытый ключ, `iss`, `aud`, где лежит токен (заголовок `Authorization` или cookie) и названия полей с логином, ФИО, почтой, подразделением и группами.
4. Какая группа AD даёт права администратора системы заявок.

### Режим `headers`

Прокси портала после входа через AD добавляет к запросу заголовки `X-Remote-User`, `X-Remote-Name`, `X-Remote-Email`, `X-Remote-Department`, `X-Remote-Groups`. Имена настраиваются.

Заголовки принимаются **только от адресов из `TRUSTED_PROXIES`**. Иначе любой, кто доберётся до сервиса напрямую, сможет подставить чужой логин. Цепочка устроена так:

```
браузер → прокси портала (10.0.0.10) → nginx (контейнер frontend) → backend
```

- nginx дописывает адрес прокси портала в `X-Forwarded-For`;
- uvicorn доверяет `X-Forwarded-For` только от nginx (`FORWARDED_ALLOW_IPS` — внутренняя сеть compose) и определяет адрес прокси портала;
- backend сверяет этот адрес с `TRUSTED_PROXIES`.

Дополнительно закройте порт `HTTP_PORT` на межсетевом экране для всех, кроме прокси портала.

Группы в `X-Remote-Groups` разделяются `;` или `|` и могут приходить именами или полными DN (`CN=Группа,OU=...,DC=...`).

### Режим `jwt`

Токен читается из `Authorization: Bearer …` или из cookie `JWT_COOKIE_NAME`. Подпись проверяется по `JWT_JWKS_URL`, `JWT_PUBLIC_KEY` или `JWT_SECRET`; `exp` обязателен, `iss` и `aud` проверяются, если заданы. Путь к полю можно указывать через точку, например `JWT_CLAIM_GROUPS=realm_access.roles`.

### Встраивание во фрейм и базовый путь

- `APP_BASE_PATH=/automation/` — путь, по которому портал открывает вкладку. Задаётся при сборке frontend, после изменения нужна пересборка: `docker compose up -d --build`.
- `PORTAL_ORIGINS` — адреса портала для заголовка `Content-Security-Policy: frame-ancestors`. Встроить вкладку в чужой сайт нельзя.
- Цвета и шрифт вынесены в CSS-переменные в начале `frontend/src/styles.css`: команда портала может привести вкладку к своему оформлению. Внешних шрифтов и CDN нет — интерфейс работает в закрытом контуре.

## Роли

| | Заявитель | Администратор |
|---|---|---|
| Подать заявку, видеть свои заявки | ✓ | ✓ |
| Дополнить заявку по запросу, отозвать до решения | свою | свою |
| Комментировать заявку | свою | любую, в том числе служебными заметками |
| Реестр, дашборд, смена статусов, сроки и ответственные | — | ✓ |
| Производственный календарь | — | ✓ |

Администратором становится член групп из `ADMIN_GROUPS`. Роль пересчитывается при каждом входе.

## Производственный календарь

Сроки рассмотрения (по умолчанию 5 рабочих дней, `REVIEW_BUSINESS_DAYS`) считаются с учётом праздников и переносов.

- **2025 и 2026 годы** заполнены миграцией `0002_reference_data.py`. Перед вводом в эксплуатацию сверьте их с постановлениями Правительства РФ о переносе выходных.
- **Следующие годы** администратор заполняет в разделе «Календарь», когда выходит постановление (обычно осенью). Пока год не заполнен, нерабочими считаются выходные и праздники из ст. 112 ТК РФ, но не переносы. С ноября дашборд напоминает о незаполненном следующем годе.

## Резервное копирование

Данные хранятся в двух томах Docker: `pgdata` (база) и `uploads` (приложенные файлы). Копировать нужно оба.

```bash
docker compose exec -T db pg_dump -U zayavki -Fc zayavki > zayavki-$(date +%F).dump
docker run --rm -v zayavki_uploads:/data -v "$PWD":/backup alpine tar czf /backup/uploads-$(date +%F).tgz -C /data .
```

## Разработка

### Backend

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
docker compose up -d db                   # из корня проекта
.venv/bin/alembic upgrade head
.venv/bin/python -m app.seed
.venv/bin/uvicorn app.main:app --reload   # http://127.0.0.1:8000/api/docs
```

Новая миграция после изменения `app/models.py`: `.venv/bin/alembic revision --autogenerate -m "описание"`. Проверка, что модели и миграции не расходятся: `.venv/bin/alembic check`.

### Frontend

```bash
cd frontend
npm ci
npm run dev        # http://127.0.0.1:5173, запросы /api проксируются на :8000
npm run build      # проверка типов и сборка
```

### Тесты

**Backend** — 59 тестов на настоящем PostgreSQL: доменные правила, API, авторизация, миграции. Нужна отдельная база `zayavki_test`, при каждом запуске она пересоздаётся с нуля.

```bash
docker compose exec db createdb -U zayavki zayavki_test   # один раз
cd backend && .venv/bin/python -m pytest
```

**Frontend** — 16 сквозных сценариев в Chromium, включая автоматическую проверку доступности (axe, WCAG 2.1 AA). Перед запуском демо-данные в базе разработки создаются заново; backend и Vite поднимаются сами, если ещё не запущены.

```bash
cd frontend
npx playwright install chromium   # один раз
npm run test:e2e
```

## Что исправлено по сравнению с прототипом

| Проблема прототипа | Как решено | Где проверяется |
|---|---|---|
| Кнопки в модальных окнах не работали, администратор не мог обработать заявку | Нативный `<dialog>`, каждое действие — отдельный запрос к API | e2e «принимает заявку в работу» |
| Пункт меню «Создать заявку» ронял приложение | Маршрутизация с адресами страниц: `/requests/new`, `/requests/:id` | e2e «подаёт заявку… через пункт меню» |
| Поиск и сортировка не работали | Поиск на сервере по номеру, заявителю и тексту (триграммный индекс), сортировка по любой колонке, постраничный вывод | `test_search_*`, `test_sorting_*`, e2e |
| «Мои заявки» показывали заявки всех, роль переключалась кнопкой | Пользователь и роль приходят из AD через портал, доступ проверяется на сервере | `test_applicant_sees_only_own_requests`, `test_auth.py` |
| Введённый текст терялся, «Начать заново» не очищало форму | Черновики хранятся на сервере с версиями; предупреждение при уходе с несохранёнными изменениями | e2e про черновики, `test_drafts_*` |
| Файлы не прикреплялись, имя файла позволяло внедрить разметку | Файлы действительно сохраняются, тип и размер проверяются, скачивание — только автору и администраторам | `test_file_upload_*`, e2e про файлы |
| Отрицательная трудоёмкость, минуты округлялись до нуля | Проверки на клиенте и сервере, пересчёт в человеко-часы в месяц на лету | `test_field_errors_*`, `test_short_operations_*` |
| Сроки без праздников, «новые» и просроченные считались неверно | Производственный календарь, пауза срока на время уточнения, отметка «просмотрено» | `test_calendar_*`, `test_clarification_*` |
| Плитки дашборда не сходились с общим числом | Каждая заявка входит ровно в одну группу | `test_dashboard_groups_add_up_to_total`, e2e |
| Из «Отклонена» не было выхода, нельзя было откатить статус, сменить срок, узнать, кто что сделал | Возобновление, откаты с обязательным комментарием, изменение срока и ответственного, журнал действий с автором | `test_full_lifecycle_*`, `test_assignment_*` |
| Двое одновременно затирали изменения друг друга, номера могли повторяться | Оптимистичная блокировка по версии, номер выдаётся базой атомарно | `test_stale_version_*`, `test_request_numbers_are_unique_*` |
| Форма не проходилась с клавиатуры, не было подписей полей и ARIA, низкий контраст | Настоящие поля формы, `label`, radio, связанные ошибки, `aria-live`, видимый фокус, исправленные цвета | e2e с axe и сценарием без мыши |
| Не было выгрузки и печати | Выгрузка реестра в Excel (с защитой от формул), стили для печати карточки | `test_excel_export_*`, e2e |

## Ограничения и что не сделано

- **Почта не отправляется** — так решено на этом этапе. Все уведомления приходят в раздел «Уведомления». Отправку писем можно добавить в `backend/app/services/notifications.py`: вызывающий код менять не придётся.
- Уведомления о новых заявках получают администраторы, которые **хотя бы раз заходили** в систему: до первого входа их нет в базе.
- **Справочники** регионов и тематик редактируются миграцией или SQL — отдельного экрана для них нет.
- Загружаемые файлы **не проверяются антивирусом**. Если это требуется, подключите проверку перед сохранением в `backend/app/services/documents.py`.
- Производственный календарь на 2025–2026 годы нужно сверить с официальными постановлениями, на следующие годы — заполнять вручную.
